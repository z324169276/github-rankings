# 公司电脑不能上网，怎么批量处理 PDF？

财务要合并报销单，行政要把一百份合同加水印，销售要把报价单统一转成 PDF。这些事都发生在不能连外网的内网电脑上。

多数人的处理方式是：拷到 U 盘，带回家用自己的电脑转，再拷回来。一百份文件，来回两趟，中间还可能拿错版本。

## 为什么现成的办法都不顺手

**在线转换网站**：文件要上传。合同、报价单、身份证扫描件传到别人的服务器上，这件事本身就过不了合规。很多公司明令禁止，只是没人管。

**装 Adobe Acrobat**：正版一份一两千，装十台就是两万。而且大部分人只需要合并、加水印、转格式这三个功能。

**让 IT 写脚本**：能跑，但需求一变就得重写。今天要加水印，明天要按页拆分，后天要压缩到 2MB 以内。

## 做法：在内网起一个 PDF 工具箱

找一台内网服务器，2 核 4G 就够。装好 Docker 之后，一条命令把 Stirling-PDF 跑起来：

```bash
docker run -d --name stirling-pdf \
  -p 8080:8080 \
  -v ./stirling-data:/configs \
  -e SECURITY_ENABLELOGIN=true \
  --restart unless-stopped \
  stirlingtools/stirling-pdf:latest
```

跑完之后，内网任意一台电脑用浏览器打开 `http://服务器IP:8080`，就能合并、拆分、加水印、转图片、压缩、加页码，全程不出内网。

### 三处默认配置要改

**开登录**。上面那条命令里的 `SECURITY_ENABLELOGIN=true` 就是干这个的，第一次访问会要求设置管理员账号。不加这个参数，内网谁都能进。

**挂数据卷**。`-v ./stirling-data:/configs` 把配置和账号存在宿主机上，否则容器一删全没了。

**固定版本号**。示例里写的是 `latest`，正式环境请换成具体版本，否则某天自动更新后行为变了，没人知道为什么。

### 备份

需要备份的只有 `stirling-data` 目录。加一条每日定时任务打包到另一台机器就够了，不需要备份整个容器。

## 这样做的局限

- 扫描件的 OCR 需要额外装语言包，中文识别率一般，重要文件仍要人工核对
- 单次处理几百页的大文件会吃内存，4G 内存的机器容易卡住
- 不支持 PDF 表单填写、电子签章这类高级功能
- 没有审批流，谁都能下载处理后的文件

## 什么情况别这么做

**只有一两个人偶尔用**：让他们用 WPS 或者系统自带的预览就够了，专门部署一套不划算。

**需要对接业务系统自动处理**：比如订单生成后自动合并 PDF 并归档，这是开发活，不是部署活，按项目报价，不是按部署报价。

**文件密级高到不能放在任何共享服务器上**：这种情况应该用单机版工具，处理完不落盘，而不是做成内网服务。

## 什么时候该找人

如果你公司没有能长期开机的内网服务器、没人会装 Docker、或者要求统一账号和权限管理，自己折腾的时间成本会超过找人做的费用。

判断标准很简单：这件事如果两周内没有跑通，说明它不是一个「顺手做一下」的活。
