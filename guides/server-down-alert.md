# 服务器挂了没人知道，怎么自动发通知？

半夜两点网站打不开，第二天早上客户打电话来才知道。这种事在小公司特别常见，因为没有人二十四小时盯着。

更麻烦的是：不是完全打不开，而是某个接口很慢、证书过期、磁盘满了。页面还能打开，但已经在出事。

## 先说一个容易踩的坑

很多人第一反应是「发到我微信上」。个人微信没有官方接口，所有号称能直接推到个人微信的方案，本质都是第三方挂靠或者模拟登录，随时会失效，也不合规。

能稳定用的是这三个通道：

- 企业微信群机器人（公司有企业微信的话，首选）
- 钉钉群机器人
- 飞书群机器人

如果公司只用个人微信，退一步用邮件加短信，或者用一台旧安卓手机做短信转发，不要指望个人微信接口。

## 做法：监控 + 机器人

### 第一步，起一个监控服务

一台 1 核 2G 的小机器就够，和内网服务器分开，避免业务机器挂了监控也一起挂。

```bash
docker run -d --restart=always \
  -p 3001:3001 \
  -v uptime-kuma:/app/data \
  --name uptime-kuma \
  louislam/uptime-kuma:1
```

浏览器打开 `http://服务器IP:3001`，第一次进去设置管理员账号。

### 第二步，加监控项

需要监控的通常只有四类：

| 类型 | 监控什么 | 多久检查一次 |
|---|---|---|
| HTTP | 首页、登录接口、支付回调 | 60 秒 |
| 端口 | 数据库 3306、Redis 6379 | 60 秒 |
| 证书 | HTTPS 到期时间 | 每天一次 |
| 关键字 | 返回内容里必须有某个词 | 5 分钟 |

第三种最容易漏。证书过期那天，网站不会报错，只会让所有用户看到红色警告页。

第四种用来防「页面 200 但内容是错误提示」这种情况，只监控状态码发现不了。

### 第三步，接企业微信群机器人

在企业微信群里点右上角，添加群机器人，复制 Webhook 地址。

回到 Uptime Kuma，添加通知，类型选企业微信，把 Webhook 粘进去，点测试。群里能收到消息就成了。

然后把通知挂到每个监控项上。

### 第四步，写清楚「通知了以后怎么办」

这是大多数部署做完之后缺的一环。收到告警的人如果不知道该做什么，通知等于没发。

最起码要有一页纸写清：

- 谁负责看告警
- 打不开时先查什么（服务器能不能登录、磁盘满没满、数据库连不连得上）
- 多久没恢复要升级给谁
- 哪些告警可以忽略

## 两个容易被忽略的细节

**告警风暴**。一个服务挂了，可能同时触发十条告警。Uptime Kuma 支持设置重试次数和告警间隔，建议「连续失败 2 次才告警」，重试间隔 30 秒，避免网络抖动就报警。

**监控本身也会挂**。监控机器最好和业务机器不在同一台、不在同一个机房。如果只有一台服务器，至少让监控每天给你发一条「我还活着」的消息——收不到这条消息，本身就是告警。

## 什么情况别这么做

**业务量很小**：一天几十个访问，出了问题客户会直接打电话，做一套监控的投入回收不了。

**没有明确的责任人**：告警发到群里，没人认领，三个月后所有人都会把群消息设成免打扰。

**需要做到分钟级恢复**：那需要的是值班和自动化运维，不是一个监控面板。

## 什么时候该找人

如果你没有独立的小机器、公司服务器出网受限、或者想把告警、备份、巡检合成一套，找人做比逐项折腾省时间。
