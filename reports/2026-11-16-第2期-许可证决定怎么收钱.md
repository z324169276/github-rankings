# GitHub 商业化雷达 · 第 2 期

**主题：先看许可证，再决定怎么收钱**

数据截至 2026-11-16，样本 1462 个 GitHub 热门仓库。本期换了一个切法：不按赛道分组，按**你将来能怎么收钱**分组——因为同样是"拿开源做产品"，MIT 和 AGPL 对应的是一门完全不同的生意。

---

## 本期方法论：许可证决定交付形态

很多人选项目只看星标，忽略许可证，做到一半才发现不能做闭源 SaaS。先记住这条分界线：

| 许可证 | 能做什么 | 不能做什么 |
|---|---|---|
| MIT / Apache-2.0 / BSD | 改完闭源卖、做成 SaaS、卖买断授权 | 基本没有约束，需保留版权声明 |
| GPL-3.0 | 分发时必须开源修改、卖服务与定制 | 分发闭源客户端受限；纯 SaaS 不受此约束 |
| AGPL-3.0 | 卖部署、定制、运维、咨询 | **提供网络服务也必须开源修改**，做不了闭源 SaaS |
| 无许可证 / 非商用 | 只能自己用 | 不能商用，别碰 |

所以：

- **MIT/Apache 项目** → 可以做产品（买断、订阅、闭源客户端）
- **AGPL 项目** → 只能做服务（部署费、年运维、定制开发），收款方式偏项目制

本期 12 个项目里，6 个可做产品，4 个只能做服务，2 个只适合当能力储备。

## A 组：可做产品（MIT / Apache）

### 1. Filee —— 263 种格式的离线文件转换

- **仓库**：[KnifeLemon/Filee](https://github.com/KnifeLemon/Filee) · 26366★ · 1511 fork · MIT · C#
- **是什么**：免费开源的本地文件转换器，拖拽即转，支持 263 种格式，离线运行。
- **切入点**：不要做"万能转换器"，做**单一行业的批量转换**。印刷厂要 PDF/X、档案室要 PDF/A、设计团队要图片批量转 WebP 并控制体积、财务要扫描件合成 PDF。这些场景对格式标准有硬要求，通用工具满足不了。
- **变现**：桌面工具买断 ¥99–299；批量处理服务按份计费；给企业做定制转换规则 ¥3000 起。
- **风险**：C# 桌面工具跨平台弱，若要服务 macOS/Linux 客户需要重写外壳。
- **信号**：两个月 26366★，说明"离线、不上传"是真实卖点——这正好避开客户对云端工具的数据顾虑。

### 2. PdfCraft —— 从零写的 PDF 阅读与编辑器

- **仓库**：[storytold/pdfcraft](https://github.com/storytold/pdfcraft) · 20519★ · 7532 fork · Apache-2.0 · Rust
- **是什么**：用 Rust 从零实现的 PDF 阅读器与编辑器，不是套壳。
- **切入点**：做"批处理 + 脱敏"。企业真正的痛点不是单份编辑，而是几千份合同要批量改页眉、去水印区域、抽表格、涂黑敏感字段。这类需求现在靠人工或昂贵商业软件。
- **变现**：按批处理量收费（如 ¥0.1–0.5/份）；给律所、审计、HR 做私有部署 ¥1–3 万。
- **风险**：PDF 是深坑，字体、加密、表单各版本差异极大，要做好只覆盖高频场景的准备。
- **信号**：30 天 20519★、fork 比例 36.7%，热度极高。但**高 fork 比例不等于商业验证**——这种"从零重写经典软件"的项目，fork 多数是开发者围观和动手试，不是采购信号。热度可以用来说服客户"这技术靠谱"，不能当成需求已验证。

### 3. FilmCraft —— 从零写的非线性视频编辑器

- **仓库**：[storytold/filmcraft](https://github.com/storytold/filmcraft) · 18156★ · 7400 fork · Apache-2.0 · Rust
- **是什么**：纯 Rust 实现的非线性视频编辑软件。
- **切入点**：不要做通用剪辑器。做**固定流程的批量剪辑**：口播去停顿、固定片头片尾、批量加字幕与贴片、一次导出多平台尺寸。客户要的是"每天 50 条稳定出片"，不是创作自由。
- **变现**：按条收费 ¥3–10；或做成工作室内部工具授权。
- **风险**：视频编辑工程量巨大，个人改内核不现实。正确姿势是只用它的导出/合成能力，前面接自己的模板系统。
- **信号**：41% 的 fork 比例，同样属于"工程师兴趣"而非"采购意向"，别高估。

### 4. CodexBar —— 看 AI 编码工具的用量

- **仓库**：[steipete/CodexBar](https://github.com/steipete/CodexBar) · 23140★ · 2228 fork · MIT · Swift
- **是什么**：在 macOS 菜单栏显示 OpenAI Codex、Claude Code 等工具的用量统计，不用登录网页。
- **切入点**：**团队版成本观测**。现在很多团队给十来个人开了 AI 编码订阅，但没人知道钱花在哪、谁在用、值不值。做一个能汇总多工具、多成员用量的面板，输出周报，直接对接财务。
- **变现**：按席位订阅 ¥20–50/人/月；或一次性买断团队授权。
- **风险**：依赖各家 API 与计费口径，规则变了要跟；只做 macOS 会丢掉一半客户。
- **信号**：一年内 23140★，且是"开发者给自己做的工具"——这类项目转商业化的成功率通常高于教程类。

### 5. niubigeo —— AI 搜索时代的品牌可见度

- **仓库**：[Albert-Weasker/niubigeo](https://github.com/Albert-Weasker/niubigeo) · 10246★ · 822 fork · Apache-2.0 · TypeScript
- **是什么**：开源 AI 品牌可见度与竞品报告工具，站点可自部署。
- **切入点**：这是本期**最值得做的方向**。传统 SEO 监测的是百度/谷歌排名，但用户现在直接在 AI 对话里问"哪个牌子好"。品牌方完全不知道自己在那里面被怎么提及。"AI 可见度监测 + 优化建议"是一个刚出现、还没被占满的位置。
- **变现**：品牌方月付 ¥2000–8000；代运营/MCN 按客户数打包；单次诊断报告 ¥1500 起。
- **风险**：AI 回答不稳定，同一问题多次结果不同，必须用多次采样和统计口径，否则报告不可信。这是唯一的技术门槛，也是壁垒。
- **信号**：2026-09 上线，两个月 10246★，赛道刚起。

### 6. open-seo-mcp-skills —— 把 SEO 能力做成 Agent 技能

- **仓库**：[Ryze-AI-Adgent/open-seo-mcp-skills](https://github.com/Ryze-AI-Adgent/open-seo-mcp-skills) · 9427★ · 398 fork · MIT · Shell
- **是什么**：免费的 SEO / GEO MCP Server 与技能包，供 Claude 等 Agent 直接调用。
- **切入点**：不适合单独卖。它的价值是**变成你做交付时的效率工具**——接了 SEO 或 GEO 的活，用这些技能把关键词调研、竞品分析、内容大纲自动化，把交付周期从三天压到一天。
- **变现**：不直接卖，体现在接单利润率和接单量上。
- **风险**：技能包本身免费且易复制，别指望它成为产品。

## B 组：只能做服务（AGPL）

这一组的共同点：**代码能用，但不能拿去做闭源 SaaS**。改成卖部署、定制、运维，反而更符合个人接单的现实。

### 7. DocuSeal —— 电子签名

- **仓库**：[docusealco/docuseal](https://github.com/docusealco/docuseal) · 19045★ · 1947 fork · AGPL-3.0 · Ruby
- **是什么**：开源的 DocuSign 替代品，创建、填写、签署数字文档。
- **切入点**：中小企业签合同还在"打印—签字—扫回"。给他们做一套私有电子签：合同模板、签署顺序、留痕、归档。真正的门槛不是技术，是**把他们的合同流程理清楚**。
- **变现**：部署 + 模板配置 ¥5000–15000；年维护 ¥2000–5000。
- **风险**：电子签在国内涉及《电子签名法》对可靠电子签名的要求，涉及身份核验与存证时，别自己承诺法律效力，只做流程工具，必要时引导客户接合规 CA。

### 8. Matomo —— 网站分析私有化

- **仓库**：[matomo-org/matomo](https://github.com/matomo-org/matomo) · 22028★ · 2931 fork · GPL-3.0 · PHP
- **是什么**：自托管网站分析平台，数据存在自己服务器。
- **切入点**：客户被 GA/百度统计的数据出境和广告拦截问题困扰时，私有化分析是刚需。做"合规分析部署"：迁移历史数据、配好隐私选项、出数据看板。
- **变现**：部署 ¥3000–8000；年运维 ¥1500–4000；数据迁移另计。
- **风险**：客户会拿它和免费统计工具比价格，要卖"数据合规"而不是"统计功能"。

### 9. Peach —— 本地媒体库管理

- **仓库**：[peach-mitao/peach](https://github.com/peach-mitao/peach) · 14933★ · 1744 fork · AGPL-3.0 · Python
- **是什么**：本地优先的视频元数据刮削与媒体库管理器。
- **切入点**：换成"素材资产管理"——给视频团队、MCN、婚庆摄影做本地素材库：自动识别、打标签、按项目归类、快速检索。他们的素材现在散在几十个移动硬盘里。
- **变现**：部署 + 初始化整理 ¥5000 起；按素材量报价。
- **风险**：元数据刮削依赖第三方站点，注意版权与访问规则，别把抓取做成产品卖点。

### 10. Monica —— 个人 CRM

- **仓库**：[monicahq/monica](https://github.com/monicahq/monica) · 25765★ · 2636 fork · AGPL-3.0 · PHP
- **是什么**：记录人际关系的个人 CRM，记住每个人的往来细节。
- **切入点**：改成**小团队客户台账**——不是销售 CRM，而是服务型小团队（装修、教培、私教、牙医）想知道"这个客户上次说了什么、孩子几岁、答应过什么"。这类客户用不了复杂 CRM，也不需要。
- **变现**：定制 + 部署 ¥5000–12000；按人年付 SaaS 不可行（AGPL），改成年费维护更稳。
- **风险**：需求偏软，客户说不清要什么，必须先用一个行业打样。

## C 组：只适合当能力储备

### 11. komi-store —— 开发者应用商店

- **仓库**：[komi-store/komi-store](https://github.com/komi-store/komi-store) · 20601★ · 771 fork · Apache-2.0 · Kotlin
- **是什么**：面向开发者的应用商店，直接从 GitHub Releases 分发应用。
- **切入方式**：个人做不了应用商店这门生意（两端都要规模）。但可以做**企业内部应用分发**：给一家公司搭一个内网商店，员工自己装内部工具，带版本与权限控制。
- **变现**：一次性项目 ¥1–3 万。
- **判断**：属于"有需求但没有标准答案"的项目，只在正好碰到客户时用。

### 12. Handy —— 本地语音转文字

- **仓库**：[cjpais/Handy](https://github.com/cjpais/Handy) · 38585★ · 3635 fork · MIT · Rust
- **是什么**：免费开源的本地语音转文字桌面应用，可扩展。
- **切入方式**：做**垂直听写**——律师口述笔录、医生门诊记录、记者采访整理。差别在做行业词库、固定输出格式、自动脱敏。通用听写已经免费，值钱的是行业适配。
- **变现**：买断 ¥199–499；或按团队授权。
- **风险**：本地模型效果弱于云端，必须在"隐私"和"准确率"里选一个说给客户听，别都许诺。

## 本期结论

如果只挑一个：

1. **niubigeo 方向的 AI 可见度监测** —— 新赛道、客户预算已存在、个人能交付。风险是口径要严谨，做不出可信报告就没生意。
2. **Filee / PdfCraft 方向的行业批处理** —— 需求具体、报价清晰、不需要教育市场。
3. **DocuSeal / Matomo 方向的合规部署** —— 客单价高，但要能接触到有决策权的人。

不建议做：文件转换器本身、通用 PDF 编辑器、通用视频编辑器——这些是"工具"，不是"生意"，客户会拿免费版比价。

## 筛选口径

| 维度 | 规则 |
|---|---|
| 许可证 | MIT / Apache-2.0 / BSD / ISC / GPL / AGPL，分别标注可变现方式 |
| 活跃度 | 120 天内有推送，排除已归档 |
| 体量 | 2000★ 以上、3 万★ 以下；过大的项目个人吃透成本高 |
| 排除 | 资料合集、教程、绕过授权与破解类 |
| 本期偏好 | 2025 年后新建、且有明确"企业已付费品类"对应物的项目 |
