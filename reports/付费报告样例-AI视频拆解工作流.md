# 付费报告样例｜AI 视频拆解工作流

> 这是《GitHub 商业化雷达》付费报告的结构样例。付费版每一期只深挖 **一个可执行方向**，回答四个问题：值不值得做、卖给谁、怎么做出来、怎么收钱。
>
> 本样例基于 2026-11-16 榜单数据，涉及 4 个公开仓库的真实指标。

---

## 一句话结论

**做"爆款视频拆解 + 复刻方案"的按条付费服务，用现成开源组件拼，2 周出可用版本，单条定价 50–200 元，先卖给 3 类人。**

不做生成工具，不做视频平台，只做"看懂别人怎么拍"这件事。

---

## 一、为什么是现在

四个仓库在两个月内同时出现，指向同一个缺口：

| 项目 | 星标 | Fork | 建立时间 | 它证明了什么 |
|---|---|---|---|---|
| [rea-video](https://github.com/JuneYaooo/rea-video) | 7321 | 1078 | 2026-10-29 | 逐镜头拆解 + 判断实拍/AI/代码生成，有人要做 |
| [openfilm](https://github.com/openfilm/openfilm) | 5882 | 567 | 2026-10-04 | 生成必须可编辑，纯生成没人满意 |
| [ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill) | 5170 | 439 | 2026-09-03 | 剪辑能力正在被封装成 Agent 可调用的工具 |
| [printfilm](https://github.com/yi1108/printfilm) | 7419 | 824 | 2026-09-10 | 短视频营销已被当成正式生意在做 |

**Fork / Star 比例是关键信号**：rea-video 是 14.7%，ffmpeg-skill 是 8.5%。这类比例说明用户不是收藏，是真的拿去改和用。

四个项目都在解决"生产"，没有人解决"**诊断**"。而投放团队最痛的恰恰是诊断——为什么这条素材能跑量，我该怎么复刻。

---

## 二、客户是谁

按付费意愿排序，只做前两类。

### 客户 A：中小投放团队（首选）

- 规模：3–15 人，投抖音/视频号/小红书
- 现状：靠人肉看素材，凭感觉复刻，一条爆款出来全组加班拆
- 痛点：拆得慢、拆得浅、结论不可复用
- 付费意愿：**高**。素材成本直接对应投放预算，一条有效结论能省几千块试错
- 决策链：一个人拍板，不需要走采购

### 客户 B：代运营 / MCN

- 规模：10–50 人，同时服务多个品牌
- 痛点：拆解是重复劳动，新人上手慢，交付质量不稳定
- 付费意愿：**中高**，但要能标准化、能贴自己品牌
- 价值点：不是省钱，是**交付能力可复制**

### 客户 C：个人创作者（不建议作为主客户）

- 付费意愿低，价格敏感，退款率高
- 只作为口碑和案例来源，不做定制

## 三、产品定义

### 做什么

一条视频进，一份结构化报告出：

1. **分镜表**：每个镜头的时长、画面内容、转场方式、字幕位置
2. **来源判断**：实拍 / AI 生成 / 模板代码生成，并给出判断依据
3. **结构拆解**：前 3 秒钩子类型、中段节奏、结尾引导方式
4. **复刻方案**：可执行的拍摄清单或提示词，含替代方案
5. **风险提示**：音乐版权、肖像、平台规则

### 不做什么（重要）

- 不提供原视频下载
- 不做一键生成成品视频（客户不信任，也不该我们承担内容责任）
- 不做账号数据抓取（只处理客户自己提供的素材链接或文件）
- 不做订阅制平台（前期人工交付，验证需求后再谈产品化）

### 交付形态

第一版就是 **PDF + 在线页面**。不需要做系统，用现成工具生成 HTML 再导出即可。客户要的是结论，不是后台。

## 四、技术方案

只用开源组件，不自研模型。

| 环节 | 用什么 | 说明 |
|---|---|---|
| 镜头切分 | ffmpeg 场景检测 | 直接复用 [ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill) 的工具契约 |
| 画面理解 | 多模态模型 API | 按镜头抽帧，批量送模型，控制成本 |
| 来源判断 | 规则 + 模型 | 参考 [rea-video](https://github.com/JuneYaooo/rea-video) 的判定思路 |
| 结构化输出 | 自定义模板 | 固定字段，保证每份报告结构一致 |
| 报告渲染 | HTML 模板 | 可导出 PDF，也可做成可分享链接 |

**工作量估算**

| 任务 | 说明 |
|---|---|
| 拆解流水线 | 切分 → 抽帧 → 模型分析 → 结构化，主体工作 |
| 报告模板 | 固定 5 个板块，做 2–3 个行业变体 |
| 人工校对环节 | 第一版必须人工过一遍，这是质量护城河 |

不需要前端框架，不需要数据库，不需要登录系统。

## 五、定价与交付

### 定价

| 套餐 | 内容 | 建议价 |
|---|---|---|
| 单条拆解 | 1 条视频 + 完整报告 | ¥50–200（按视频时长和复杂度） |
| 批次包 | 10 条，含横向对比与优先级排序 | ¥800–1500 |
| 团队包月 | 每月 30 条 + 1 次复盘会 | ¥2000–4000 |
| 定制模板 | 按客户行业做专属拆解模板 | ¥3000 起 |

价格原则：**按"帮客户省下的试错成本"定价，不按工时定价。**

### 交付流程

1. 客户提交视频链接或文件 + 一句需求（投什么品、目标人群）
2. 24 小时内出初稿
3. 客户提 1 轮修改
4. 交付 PDF + 可分享页面

首单建议免费做 2 条，换真实反馈和案例授权。第 3 单开始收费。

### 获客

- 在投放/电商社群发**拆解样例**，不发广告
- 把每条公开案例做成对比图：原视频结构 vs 复刻后数据
- 用榜单里 `printfilm`、`rea-video` 这类项目的讨论区找早期用户

## 六、成本与收益（按假设测算）

以下为模型假设，不是市场数据，请按自己的实际情况替换。

| 项目 | 假设 |
|---|---|
| 单条模型成本 | ¥1–3（按 60 秒视频、20 个镜头、每镜头 3 帧估算） |
| 单条人工校对 | 15–25 分钟 |
| 单条售价 | ¥100（中位数） |
| 月产能（兼职） | 40–60 条 |

结论：**毛利结构很健康，瓶颈不在成本，在获客。** 所以第一优先级是把样例做出来，不是把系统做完美。

## 七、30 天执行清单

**第 1 周：做出能看的样例**

- [ ] 挑 1 个熟悉行业，选 5 条该行业爆款
- [ ] 用 ffmpeg 切分 + 抽帧，手工跑通一遍流程
- [ ] 定死报告模板的 5 个板块，写成固定结构
- [ ] 产出 2 份完整样例报告

**第 2 周：把流程跑顺**

- [ ] 把切分、抽帧、模型分析串成脚本，一条命令出初稿
- [ ] 记录每条的真实耗时和模型成本
- [ ] 找 3 个目标客户，免费送样例，收集反馈

**第 3 周：收第一笔钱**

- [ ] 按反馈改模板，补上客户最在意的板块（通常是复刻方案）
- [ ] 定价格，写清楚交付边界和修改次数
- [ ] 成交第 1 单，哪怕打折

**第 4 周：决定是否加码**

- [ ] 复盘：成交率、单条耗时、客户复购意向
- [ ] 如果 3 单里有 2 单复购，投入做批量化
- [ ] 如果没人愿意付，换行业再试一次，不要加功能

## 八、风险与红线

| 风险 | 应对 |
|---|---|
| 视频版权 | 只处理客户提供的素材，不转存、不二次分发 |
| 平台规则 | 不提供下载工具，不做账号数据抓取 |
| 模型判断出错 | 报告标注"AI 辅助判断"，关键结论人工复核 |
| 同质化 | 壁垒在行业模板和案例积累，不在技术 |
| 客户流失 | 用批次包和包月锁定复购，单条只做引流 |

**红线**：不碰破解、不碰去水印、不碰搬运洗稿。这三件事来钱快，但会让整个生意一次性归零。

---

## 九、什么时候该放弃

出现以下任一情况，停止投入：

- 做完 10 条样例，没有 1 个客户愿意付费
- 单条人工校对超过 40 分钟，且无法通过模板压缩
- 客户只想要"生成成品"，不认可"拆解方案"的价值
- 连续 2 个月成交低于 5 单
