# GitHub 商业化雷达 · 第 4 期

**主题：按交付难度选项目，而不是按项目热度**

前两期分别按许可证、按客户预算分组。这一期换个视角：同样一个项目，别人报价 3000，你报价 3 万，差别通常不在技术，而在你要承担多少"不能出错的动作"。难度决定了你的报价上限，也决定了你会不会赔钱。

数据截至 2026-11-16，样本 1462 个 GitHub 热门仓库。

---

## 先把"难度"拆开

难度不是感觉，是四个可数的变量。报价前先把这四项问清楚：

| 变量 | 具体问什么 | 答错的后果 |
|---|---|---|
| 环境 | 部署在客户机房、云主机，还是内网隔离环境？有没有 root？ | 装不上，或装上了连不通 |
| 数据 | 有多少历史数据要迁？格式有多脏？谁负责核对？ | 迁完对不上账，尾款收不回 |
| 对接 | 要不要接企业微信/钉钉/SSO/旧 ERP/支付？ | 工期翻倍，且不在原报价内 |
| 责任 | 数据丢了谁赔？要不要 SLA？涉不涉及备案与等保？ | 出一次事故赔掉整单利润 |

四个变量都简单，就是一星；任意两项变复杂，就是三星；四项全踩，个人接不了。

---

## 一星：装完就能用（0.5–1 天）

这一档的共同点：单文件或单容器、无外部依赖、无数据迁移、出问题重装即可。**卖的不是技术，是"客户不想自己折腾"。**

### 1. PocketBase —— 一个文件的后端

- **仓库**：[pocketbase/pocketbase](https://github.com/pocketbase/pocketbase) · 61600★ · 3771 fork · MIT · Go
- **交付动作**：下载二进制，`./pocketbase serve`，进后台建表，配好域名反代。
- **为什么是一星**：SQLite 内嵌，没有数据库要装；后台自带，不需要写管理界面。
- **最容易翻车的一步**：SQLite 不适合多人高频写入，客户如果拿它当主业务库，半年后要重构。交付时必须写清楚适用边界。
- **报价**：单次部署 800–2000 元；做成"内部小工具"打包（表单、审批、库存台账）可到 3000–6000 元。
- **复购**：备份脚本 + 季度巡检，年费 1000–2000 元。

### 2. Stirling-PDF —— 本地 PDF 工具箱

- **仓库**：[Stirling-Tools/Stirling-PDF](https://github.com/Stirling-Tools/Stirling-PDF) · 96451★ · 9344 fork · 许可待核对（GitHub 未识别为标准协议）· TypeScript/Java
- **交付动作**：一条 docker compose，配好上传大小限制和反向代理。
- **客户场景**：律所、财务、学校——文件不能上公有云，但又要合并、拆分、加水印、OCR。
- **最容易翻车的一步**：OCR 语言包和大文件内存占用。默认配置处理 100MB 以上文件会超时，要提前调 JVM 和内嵌服务参数。
- **报价**：2000–5000 元/次，含内网部署与三个月的使用答疑。
- **注意**：许可证不是常见标准协议，给客户做商业交付前必须逐条读一遍授权条款，尤其是二次分发和改名发布。

### 3. Uptime Kuma —— 自托管监控

- **仓库**：[louislam/uptime-kuma](https://github.com/louislam/uptime-kuma) · 93581★ · 8704 fork · MIT · JavaScript
- **交付动作**：docker 起一个，加监控项，配企业微信/邮件通知。
- **为什么是一星**：界面即配置，不需要写代码；客户看得懂，验收快。
- **最容易翻车的一步**：通知渠道。企业微信机器人、钉钉加签、SMTP 被当成垃圾邮件，这三个坑至少要各踩一次。
- **报价**：1500–3500 元/次。**真正值钱的是"帮客户定监控清单"**——监控哪些地址、阈值多少、谁值班，这部分可以单独收 2000 元咨询费。
- **复购**：按年收"监控代维"，每月给一份可用性报告，3000–8000 元/年。

### 4. Gogs —— 轻量自建 Git

- **仓库**：[gogs/gogs](https://github.com/gogs/gogs) · 47927★ · 5081 fork · MIT · Go
- **交付动作**：单二进制 + SQLite/MySQL，初始化后建组织和仓库。
- **适用**：不想用 GitHub/GitLab、又只需要基本代码托管与权限的小团队（10–50 人）。
- **最容易翻车的一步**：从别的平台迁仓库和权限。Gogs 没有一键迁移，得写脚本，这部分要单独报价。
- **报价**：部署 2000 元；含迁移 5000–10000 元（按仓库数量）。
- **风险**：Gogs 迭代慢，客户如果要 CI/CD，直接推 GitLab 或 Gitea，别硬扛。

## 二星：要配环境、要迁数据（2–5 天）

比一星多两件事：状态数据要保住，客户已有的东西要搬进来。**这一档的利润点在"迁移"，不在"安装"。**

### 5. Vaultwarden —— 兼容 Bitwarden 的密码库

- **仓库**：[dani-garcia/vaultwarden](https://github.com/dani-garcia/vaultwarden) · 70653★ · 3444 fork · AGPL-3.0 · Rust
- **交付动作**：docker + 反向代理 + HTTPS + 备份；导入客户 Excel 里的密码清单。
- **为什么是二星**：密码是"丢了就完蛋"的数据，备份和恢复演练是交付的一部分，不是可选项。
- **最容易翻车的一步**：客户用手机 App 连自建服务，必须 HTTPS + 有效证书，自签证书在 iOS 上直接失败。
- **报价**：3000–8000 元（含导入与恢复演练）；20 人以上企业版可到 1.2 万。
- **许可证提醒**：AGPL-3.0，你改了代码又对外提供服务，需要开源改动。做私有部署收服务费没问题。

### 6. NocoDB —— 把 Excel 变成内部系统

- **仓库**：[nocodb/nocodb](https://github.com/nocodb/nocodb) · 65517★ · 5136 fork · 许可待核对（GitHub 未识别为标准协议）· TypeScript
- **交付动作**：部署 + 连客户数据库 + 按业务建表 + 配权限 + 导入历史表格。
- **为什么是二星**：装很快，**建模和清洗历史数据占 80% 工时**。
- **最容易翻车的一步**：客户给你 12 个 Excel，字段名不一致、有合并单元格、有手写备注。一定要先做一份"字段对照表"让客户签字，否则验收时全是争议。
- **报价**：单表/单流程 5000–15000 元；整套进销存台账 3–8 万。
- **关键话术**：报价里明确"数据清洗按表另计"，这一条能救很多单。

### 7. Docling —— 文档转结构化数据

- **仓库**：[docling-project/docling](https://github.com/docling-project/docling) · 70514★ · 5332 fork · MIT · Python · 2024-07 建
- **交付动作**：起服务，把客户的 PDF/Word/扫描件批量转成 Markdown 或 JSON，接进他们的检索或知识库。
- **为什么是二星**：代码量小，但**每批文档的版式都不一样**，效果验收标准很难定。
- **最容易翻车的一步**：扫描件与复杂表格。纯文字 PDF 准确率很高，双栏排版和盖章扫描件会明显下降。必须先拿 20 份样本跑一遍再报价。
- **报价**：按"每万页"计价，1–3 万；或做成常驻解析服务，年费 2–5 万。
- **风险**：客户会拿"识别错一个字"来压价，合同里要约定抽样合格率，而不是要求 100%。

### 8. Hoppscotch —— 自托管 API 调试平台

- **仓库**：[hoppscotch/hoppscotch](https://github.com/hoppscotch/hoppscotch) · 80791★ · 6238 fork · MIT · TypeScript
- **交付动作**：docker 部署 + 账号体系 + 团队空间 + 导入 Postman 集合。
- **为什么是二星**：客户团队已经在用 Postman，迁移成本和习惯阻力比技术难度大。
- **最容易翻车的一步**：导入 Postman 集合后环境变量、鉴权脚本不完整，需要人工修。按集合数量报价。
- **报价**：部署 + 迁移 5000–12000 元；给研发团队做"内部 API 文档门户"可到 2 万。
- **适合谁**：能进技术团队内部说话的人。这一档卖的是"替研发省事"，决策链短。

## 三星：要对接客户现有系统（1–3 周）

这一档开始出现"看不见的工时"：SSO、旧系统、审批流、权限模型。**报价必须按"对接点数量"算，不能按项目算。**

### 9. Chatwoot —— 多渠道客服台

- **仓库**：[chatwoot/chatwoot](https://github.com/chatwoot/chatwoot) · 39739★ · 9659 fork（24.3%）· 许可待核对（GitHub 未识别为标准协议）· Ruby
- **交付动作**：部署（Rails + Postgres + Redis + Sidekiq）→ 接微信公众号/网站/邮件 → 配客服分组与分配规则 → 接客户 CRM。
- **为什么是三星**：三个外部渠道 + 一个内部系统，每个对接都可能卡住。fork 比例 24.3%，说明改它的人多，也说明"默认功能不够用"是常态。
- **最容易翻车的一步**：微信公众号接入。认证、服务器地址校验、消息加解密，任一处配错就收不到消息，且日志不明显。
- **报价**：基础部署 1.5 万；每接一个渠道 +3000–6000；接 CRM +1–2 万。整套 3–6 万。
- **复购**：客服系统是天天用的，运维年费 1–3 万很自然。

### 10. Twenty —— 开源 CRM

- **仓库**：[twentyhq/twenty](https://github.com/twentyhq/twenty) · 60857★ · 10074 fork · 许可待核对（GitHub 未识别为标准协议）· TypeScript · 2022-12 建
- **交付动作**：部署 + 按客户销售流程改对象和字段 + 导入客户与商机数据 + 接邮件和日历。
- **为什么是三星**：CRM 的难点从来不是软件，是**客户说不清自己的销售流程**。字段设计错，三个月后就要重做。
- **最容易翻车的一步**：数据导入。旧 CRM 导出的客户常常一人多条、公司名写法不一，去重规则必须提前和客户确认。
- **报价**：5–15 万（含流程梳理）。如果客户只要"能用的 CRM"，3 万也能做，但要明确不含流程咨询。
- **风险**：项目新（2022 年），版本迭代快，升级可能破坏自定义字段。合同里写明"升级另计"。

### 11. Ghost —— 会员制内容站

- **仓库**：[TryGhost/Ghost](https://github.com/TryGhost/Ghost) · 55800★ · 12134 fork · MIT · TypeScript
- **交付动作**：部署 + 主题定制 + 域名与邮件（Mailgun 等）+ 支付（Stripe）+ 会员分层 + 内容迁移。
- **为什么是三星**：内容站的难点在"发布链路"——邮件送达率、订阅付费、SEO、CDN，每一项都要单独调。
- **最容易翻车的一步**：邮件。自建 SMTP 发订阅邮件，很容易进垃圾箱，必须用专业邮件服务并配好 SPF/DKIM/DMARC。
- **报价**：建站 8000–20000 元；主题定制另计 5000–15000 元。
- **注意**：Stripe 在国内主体开户有门槛。面向国内读者的付费会员，要换成微信/支付宝方案，这部分工作量要单独评估。

## 四星：要团队、要资质（1 个月以上）

这一档不是"技术更难"，而是**责任更重**：数据不能丢、服务不能停、出了事要有人兜。个人可以参与，但不要独立承接整体交付。

### 12. Nextcloud —— 私有云盘与协同

- **仓库**：[nextcloud/server](https://github.com/nextcloud/server) · 37499★ · 5352 fork（14.3%）· AGPL-3.0 · PHP
- **交付动作**：部署 + 存储规划 + LDAP/AD 对接 + 客户端分发 + 历史文件迁移 + 备份与容灾。
- **为什么是四星**：一旦成为公司文件主存储，"停一小时"就是事故。个人没有值班能力，不要接整体运维。
- **最容易翻车的一步**：从群晖/Windows 共享迁移几十 TB 文件，权限和同名冲突处理会拖很久，且客户会全程盯着。
- **报价**：部署 + 迁移 5–15 万；年运维 3–8 万（必须含响应时间承诺，谨慎签）。
- **个人可行姿势**：只做"部署 + 迁移"这一段，运维交给客户 IT 或第三方；或作为团队一员参与。

### 13. OpenProject —— 项目管理

- **仓库**：[opf/openproject](https://github.com/opf/openproject) · 17325★ · 3758 fork（21.7%）· GPL-3.0 · Ruby
- **交付动作**：部署 + 项目模板 + 权限角色 + 与 Git/CI 打通 + 培训。
- **为什么是四星**：这类系统的价值在"全员用起来"，交付包含组织变革，不只是装软件。
- **最容易翻车的一步**：没人用。上线后三个月活跃度归零，客户会认为是你的问题。
- **报价**：10–30 万（含培训与推广）；单纯部署 3–5 万，但很难验收。
- **建议**：把"培训 + 三个月陪跑"写进合同，这是这类项目唯一能验收的部分。

### 14. Discourse —— 社区论坛

- **仓库**：[discourse/discourse](https://github.com/discourse/discourse) · 48078★ · 9061 fork（18.8%）· GPL-2.0 · Ruby
- **交付动作**：部署（官方 docker 方案）+ 邮件 + SSO + 分类结构设计 + 反垃圾配置 + 内容种子。
- **为什么是四星**：社区是运营产品，不是软件产品。上线只是开始，前三个月没人运营就会死。
- **最容易翻车的一步**：邮件送达与反垃圾。发信域名没配好，用户收不到激活邮件，注册直接归零。
- **报价**：部署 2–5 万；"上线 + 三个月运营陪跑" 8–15 万。
- **风险**：国内访问与备案。放在国内服务器需要备案，放境外速度差，这个决策要客户自己做。

### 15. Grafana —— 可观测性看板

- **仓库**：[grafana/grafana](https://github.com/grafana/grafana) · 77873★ · 14968 fork · AGPL-3.0 · TypeScript
- **交付动作**：部署 + 接数据源（Prometheus/Loki/MySQL）+ 建看板 + 配告警 + 值班流程。
- **为什么是四星**：装 Grafana 是一小时的事，**建出客户愿意看的看板是几周的事**，而且要懂客户的业务指标。
- **最容易翻车的一步**：数据源本身没准备好。客户以为买的是"监控"，实际上缺的是指标采集，这部分工作量常被漏报。
- **报价**：部署 1–2 万；"指标梳理 + 看板 + 告警" 5–15 万。
- **个人可行姿势**：做垂直行业看板模板（如电商、SaaS、制造业产线），一次做好反复卖。

### 16. Immich —— 自托管照片库

- **仓库**：[immich-app/immich](https://github.com/immich-app/immich) · 119039★ · 7578 fork · AGPL-3.0 · TypeScript · 2022-02 建
- **交付动作**：部署 + 存储规划 + 手机端批量上传 + 从 iCloud/群晖迁移 + 人脸识别索引。
- **为什么是四星**：照片是"情绪资产"，客户容错率极低；且 GPU/存储成本要提前算清，否则跑起来卡。
- **最容易翻车的一步**：首次全量导入几十万张照片，缩略图与人脸索引会跑很久，期间服务几乎不可用。必须规划导入窗口。
- **报价**：家庭/小团队 5000–15000 元；企业 3–8 万（含存储方案）。
- **注意**：项目迭代非常快，升级前必须看 breaking changes，别给客户开自动更新。

### 17. Home Assistant —— 智能家居中枢

- **仓库**：[home-assistant/core](https://github.com/home-assistant/core) · 92272★ · 39303 fork（42.6%）· Apache-2.0 · Python
- **交付动作**：部署 + 接入设备 + 写自动化 + 做面板 + 现场调试网络。
- **为什么是四星**：**必须到现场**。设备协议、Wi-Fi 覆盖、弱电箱位置，任何一项在远程都判断不了。
- **最容易翻车的一步**：客户家里的网络。摄像头、网关、路由器混在一起，IP 冲突和 2.4G/5G 混频会让设备频繁掉线，这不算你的技术问题但算你的交付问题。
- **报价**：按点位计价，每点位 300–800 元；一套三居室 2–6 万。
- **fork 比例 42.6% 解读**：这个数字高，是因为大量用户把配置仓库 fork 出来做版本管理，不等于商业定制需求。别被数字误导。

## 按难度报价：一张对照表

| 难度 | 典型工时 | 报价区间 | 失败成本 | 适合谁 |
|---|---|---|---|---|
| 一星 装完就能用 | 0.5–1 天 | 800–5000 元 | 重装一次 | 刚起步，需要案例和口碑 |
| 二星 配环境 + 迁数据 | 2–5 天 | 3000–15000 元 | 返工重迁 | 有基础运维能力 |
| 三星 对接现有系统 | 1–3 周 | 1.5–15 万 | 尾款收不回 | 能直接和客户 IT/业务对话 |
| 四星 团队与资质 | 1 个月以上 | 5–30 万 + 年费 | 事故赔偿 | 有团队或作为团队一员 |

三条定价纪律：

1. **按"不能出错的动作"数量报价，不按代码量。** 客户感知不到你写了多少行，只感知到有没有出事。
2. **一星不要做定制，二星不要跳过数据清洗，三星不要口头承诺对接，四星不要独自签 SLA。**
3. **难度低不等于赚得少。** 一星做成标准包（同一套脚本、同一份文档、同一份报价），一个月跑 5 单，比一个三星项目稳。

## 交付前必须问的 6 个问题

1. 服务器谁提供？有没有 root 权限？能不能出网？
2. 要迁多少数据？谁负责核对？核对标准是什么？
3. 需要对接哪些系统？每个系统谁配合？对方有没有接口文档？
4. 上线时间点是不是绑了某个业务节点（大促、审计、开业）？
5. 出故障时找谁？响应时间要求是多少？
6. 验收标准写在哪？谁签字？

第 6 条最关键。**没有书面验收标准的项目，等于没有终点。**
