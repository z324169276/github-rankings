# GitHub 商业化雷达 · 第 3 期

**主题：按客户预算选项目，而不是按星标**

数据截至 2026-11-16，样本 1462 个仓库。前两期回答"做什么"，这一期回答**"卖给谁、多少钱、多久成交"**。

同一个项目，卖给个体户和卖给中型企业，是两门完全不同的生意。选项目之前，先想清楚你要进哪一档。

---

## 四档预算，四种生意

| 档位 | 客户 | 决策人 | 成单周期 | 典型单价 | 你的角色 |
|---|---|---|---|---|---|
| 千元级 | 个人、小店主、工作室 | 老板本人 | 当天—3 天 | ¥300–3000 | 卖工具或单次服务 |
| 万元级 | 10–50 人小企业 | 老板 / 部门负责人 | 1–4 周 | ¥5000–3 万 | 部署 + 配置 + 培训 |
| 十万级 | 中型企业、机构 | 部门 + 采购 + IT | 2–4 个月 | ¥8 万–30 万 | 项目交付，常需投标 |
| 百万级 | 大型企业、政府 | 招投标 | 6 个月以上 | — | 个人接不了，只能分包 |

**关键判断**：千元级的价值不是利润，是获客和案例；万元级才是个人能稳住的现金流；十万级一个人接不住，但可以做其中一个模块。

---

## 千元级：当场能收钱的三个

这一档客户不写需求文档，看到效果就付钱。所以交付物必须一眼可见。

### 1. SmsForwarder —— 短信与通知的转发中枢

- **仓库**：[pppscn/SmsForwarder](https://github.com/pppscn/SmsForwarder) · 28852★ · 3519 fork · BSD-2-Clause · Kotlin
- **是什么**：把安卓手机的短信、来电、应用通知，按规则转发到钉钉、企业微信、飞书机器人。
- **卖什么**：**告警通道搭建**。小公司用验证码短信、监控短信，但没人盯着，出问题几小时后才知道。配一台旧安卓机 + 规则，把短信按关键词分流到对应群，异常立刻提醒。
- **报价**：单机配置 ¥300–800；多机 + 关键词分流 + 交接文档 ¥1500。
- **为什么能成**：客户不懂技术也能看懂效果——"短信来了，群里立刻响"。演示成本几乎为零。
- **风险**：依赖一台常开的安卓设备，要提前说清断网、关机、系统杀后台的失效场景，否则会被当成 bug。

### 2. GoAccess —— 服务器日志变成看板

- **仓库**：[allinurl/goaccess](https://github.com/allinurl/goaccess) · 21130★ · 1212 fork · MIT · C
- **是什么**：实时 Web 日志分析器，终端和浏览器都能看，单个二进制文件。
- **卖什么**：给有独立站或小程序后端的小客户做**访问分析**——哪些页面被爬、哪来的流量、哪个接口在报错。他们装了统计代码，但看不到服务器层面的事。
- **报价**：部署 + 报告模板 ¥800–1500；加月度报告 ¥300/月。
- **判断**：这是"顺带卖"的服务，适合已经给对方做过网站的人。单独去卖很难开口。

### 3. Quarkdown —— 文档一键成册

- **仓库**：[iamgio/quarkdown](https://github.com/iamgio/quarkdown) · 16379★ · 525 fork · GPL-3.0 · Kotlin
- **是什么**：把 Markdown 扩展成能出论文、演示、静态站点的排版工具。
- **卖什么**：**技术文档成册**。给软件公司做产品手册、给培训机构做教材、给律所做规范汇编，要求统一版式、自动目录、可导出 PDF。
- **报价**：单本排版 ¥500–1500；长期模板维护 ¥500/月。
- **风险**：这是手工服务，不是软件，做到第三本就要考虑模板化，否则纯耗时间。

## 万元级：个人现金流的主力

这一档客户会问"能不能对接我们现有的系统"，也会拖尾款。定价要含返工。

### 4. UnoPIM —— 商品资料与数字资产

- **仓库**：[unopim/unopim](https://github.com/unopim/unopim) · 11064★ · 193 fork · MIT · PHP
- **是什么**：开源的商品信息管理（PIM）与数字资产管理，2024 年新项目。
- **卖什么**：**给多平台卖家做商品资料中台**。同一款货要在淘宝、京东、抖音、独立站上架，标题、属性、图片规格各不一样，现在靠 Excel 人工复制。做一套统一录入、批量导出、各平台模板映射。
- **报价**：部署 + 字段建模 + 首批 500 个 SKU 导入 ¥1.5–3 万；后续按 SKU 增量收费。
- **为什么值这个价**：客户算得清账——一个人每天复制粘贴 4 小时，一年就是一个人力成本。
- **风险**：SKU 数据脏是常态，报价必须写明"数据清洗另计"，否则会被拖死。

### 5. Zammad —— 客服工单系统

- **仓库**：[zammad/zammad](https://github.com/zammad/zammad) · 6113★ · 1098 fork · AGPL-3.0 · Ruby
- **是什么**：开源客服工单/帮助台系统，多渠道接入。
- **卖什么**：**把散落的客服入口收成一套工单**。客户现在有微信、电话、邮箱、抖音私信四个入口，谁在处理、处理到哪一步全靠人记。
- **报价**：部署 + 渠道接入 + SLA 规则配置 ¥1.5–3 万；年维护 ¥3000–6000。
- **注意**：AGPL，做闭源 SaaS 不行，但私有部署和定制没问题——这一档客户本来就要私有部署，许可证反而不是障碍。
- **风险**：客户真正缺的是流程规范，不是软件。上线前要帮他把"谁负责什么"写清楚，否则系统上线三天就废。

### 6. litemall —— 小程序商城

- **仓库**：[linlinjava/litemall](https://github.com/linlinjava/litemall) · 20406★ · 7312 fork · MIT · Java
- **是什么**：Spring Boot 后端 + Vue 管理端 + 微信小程序 + 移动端的完整商城方案。
- **卖什么**：**给本地商家做能自己运营的小程序店**。烘焙、花店、社区团购，需求就是商品、下单、配送、优惠券。
- **报价**：基础版 ¥5000–12000；加会员体系、分销、对接同城配送 ¥2–3 万。
- **信号**：fork 比例 35.8%，2018 年的项目至今还在被大量二次开发——**老项目的高 fork 比例才是真需求信号**（对应第 2 期说的"新项目高 fork 是围观"）。
- **风险**：小程序要客户自己的主体资质与类目，别答应"我帮你上线"；支付需要商户号，个人做不了。

### 7. Firefly III —— 小团队记账

- **仓库**：[firefly-iii/firefly-iii](https://github.com/firefly-iii/firefly-iii) · 25235★ · 2417 fork · AGPL-3.0 · PHP
- **是什么**：个人财务管理工具，支持多账户、预算、报表、银行导入。
- **卖什么**：**小团队/个体户的收支台账**。不是替代财务软件，而是解决"老板自己想知道钱去哪了"。
- **报价**：部署 + 科目设置 + 历史数据导入 ¥3000–8000。
- **判断**：这一档里最弱的一项，因为客户容易觉得"Excel 也能做"。只有在客户明确要求"多账户对账 + 自动分类"时才值得接。

## 十万级：个人只能做其中一块

这一档要资质、要发票、要能扛延期。一个人接整包风险极高，现实做法是给集成商做分包，或者只交付一个模块。

### 8. ruoyi-vue-pro —— 定制开发的底座

- **仓库**：[YunaiV/ruoyi-vue-pro](https://github.com/YunaiV/ruoyi-vue-pro) · 40386★ · 8670 fork · MIT · Java
- **是什么**：国内常用的后台管理脚手架，自带权限、工作流、多租户、支付等模块。
- **卖什么**：**不是卖它，是拿它当交付底座**。客户要一套内部管理系统，你用现成模块拼，报价按功能模块算，而不是按人天算。
- **报价**：单模块 ¥2–5 万；整套系统 ¥10–30 万（个人只接其中 2–3 个模块）。
- **信号**：fork 21.5%，是国内外包与私活的高频底座——意味着竞争也激烈，你能赢的点是行业理解，不是技术。
- **风险**：这个名字下的"Pro 版"有商业授权条款，接单前务必确认你用的是开源版还是收费版，别把授权成本算漏。

### 9. yudao-cloud —— 微服务版本

- **仓库**：[YunaiV/yudao-cloud](https://github.com/YunaiV/yudao-cloud) · 19784★ · 4930 fork · MIT · Java
- **是什么**：上面项目的 Spring Cloud 微服务版。
- **卖什么**：客户明确要求"微服务架构"时才会用到。多数中小企业并不需要，用微服务反而增加运维成本。
- **判断**：**只在客户已经这么要求时用**，不要主动推荐。主动上微服务是给自己埋运维的坑。

### 10. Canvas LMS —— 培训机构的教学系统

- **仓库**：[instructure/canvas-lms](https://github.com/instructure/canvas-lms) · 6914★ · 3064 fork · AGPL-3.0 · Ruby
- **是什么**：老牌开源学习管理系统，课程、作业、评分、讨论全套。
- **卖什么**：给职业培训机构、企业内训做**课程与考核平台**，尤其是需要"线上课 + 作业 + 证书"的场景。
- **报价**：部署 + 课程结构迁移 ¥8–15 万；定制报表与对接 HR 系统另计。
- **风险**：Ruby 技术栈，国内能维护的人少；客户后续找不到人接手，会成为你的长期负担。要么准备好长期维护合同，要么别接。
- **信号**：fork 44.3%，是本期最高，说明二次开发需求真实且持续——但同时说明改造量大，个人容易陷进去。

### 11. Spree —— B2B 电商

- **仓库**：[spree/spree](https://github.com/spree/spree) · 15832★ · 5319 fork · BSD-3-Clause · Ruby
- **是什么**：开源电商平台，支持 DTC、B2B、多商户。
- **卖什么**：**多商户或 B2B 报价型电商**——批发、经销、有阶梯价和账期的生意，标准 SaaS 商城满足不了。
- **报价**：¥10 万起，个人做不了整包，适合做其中"价格与账期模块"。
- **判断**：这一项更适合当技术储备，等有客户找上门再学。

## 从千元级爬到万元级

绝大多数人卡在这一步：能接小活，接不到大活。三个具体动作：

1. **同一个客户卖第二次**。千元级做完，主动给一份《现状问题清单》，指出三个他还没意识到的问题。第二单成交率远高于找新客户。
2. **把交付物标准化**。报价单、部署清单、验收标准、交接文档——四份文档齐了，客户才敢给你万元级。没有文档，客户默认你是"帮忙的"。
3. **找集成商当分包**。十万级项目里，总有没人愿意做的模块（数据迁移、旧系统对接、报表）。接这种模块，不需要资质，单价还不低。

## 报价与合同要点

| 事项 | 建议 |
|---|---|
| 首付 | 不低于 50%，部署类可以 70% |
| 验收 | 写可勾选的功能清单，不写"满足需求" |
| 数据 | 明确"数据清洗另计"，SKU/客户/历史数据最容易失控 |
| 源码 | 交付源码要另加价，或只交付部署产物 |
| AGPL 项目 | 合同里说明提供的是部署与定制服务，不提供闭源 SaaS |
| 拖尾款 | 分期节点绑定可演示的成果，不绑时间 |

## 本期结论

- 想**这个月就有收入**：SmsForwarder 告警通道、GoAccess 访问看板，单价低但成交快。
- 想**建立稳定现金流**：UnoPIM 商品资料、Zammad 客服工单、litemall 小程序商城，都是"客户已经在花钱"的品类。
- **不要碰**：微服务版脚手架推荐给不需要的客户、Canvas LMS 这种技术栈冷门又改造量大的系统，除非你准备长期维护。

## 筛选口径

| 维度 | 规则 |
|---|---|
| 许可证 | MIT / Apache / BSD / GPL / AGPL，均在文中标注交付边界 |
| 活跃度 | 120 天内有推送，排除已归档 |
| 体量 | 2500★ 以上、3 万★ 以下 |
| 排除 | 资料合集、教程、破解与绕过授权类、需整支团队维护的基础设施 |
| 本期偏好 | 有明确"谁付钱、付多少"对应关系的业务系统 |

## 免责

报价区间为公开市场常见水平的参考值，受地区、行业、客户规模影响很大，不构成承诺。二次开发前请核对许可证条款（尤其 AGPL 与"Pro 版"商业授权），并确认目标行业是否需要资质。涉及支付、教育、医疗等场景，务必先确认合规边界。
